# 원문 읽기 기준

## 원문 보존과 읽기

- 사용자가 붙여넣은 본문은 UTF-8 텍스트로 저장한다. URL은 승인된 브라우징 도구로 가져와 본문과 URL을 함께 보존한다. 가져오기 실패는 읽은 것이 아니다. 검색 스니펫으로 RFP 전문을 대신하지 않는다.
- 작성자/기관, 게시일, 수집일, URL, 종류, 공개 여부, 읽은 범위를 분리해 기록한다. 모르면 null 또는 '미확인'. 수집일은 게시일이 아니다.
- 형식별 읽기 절차. 본문을 먼저 전부 읽고, 표·그림이 있는 페이지만 이미지로 본다. 파일 전체를 Read에 넣지 않는다(대용량 PDF는 렌더링 오류를 낸다).
  - 텍스트·붙여넣기: 그대로 읽는다.
  - 이미지 캡처: Read로 직접 본다. 글자가 흐리면 `tesseract`로 보조하되 OCR 결과를 원문으로 취급하지 않는다.
  - PDF: `pdftotext -layout` 으로 본문. 표·그림 페이지는 `pdftoppm -png -r 110 -f N -l N` 으로 렌더해 Read로 본다.
  - HWP/HWPX: `rhwp export-text`, `rhwp export-tables`(병합 셀 보존 JSON), `rhwp export-pdf` 순으로 뽑고 그림은 PDF 절차를 따른다. `rhwp`가 없으면 HWP는 '미확인'으로 두고 설치를 안내한다(github.com/edwardkim/rhwp 릴리스 바이너리).
  - DOCX: `pandoc` 또는 zip 안 XML. 그림은 `pdf` 변환 후 PDF 절차.
- 페이지·절·줄 위치를 남긴다. 발췌만 있으면 범위를 표시하고 전체 결론을 피한다. 못 읽은 부분(예: '그림 3 이미지 미확인')을 숨기지 않는다.
- 추가하기 전에 기존 기록과 비교한다. 스크립트는 같은 store(signals/library) 안 같은 해시의 정확 중복만 잡는다(signals는 같은 organization까지). 재게시·개정본은 `--related-to`/`--relation`으로 연결하고 새 수요 그룹으로 세지 않는다.

## 채용공고

역할·연차를 추출하되 직함을 기술로 등치하지 않는다. 필수/우대, 담당 업무, 특정 기술 제약, 팀 단위 성과를 구분한다. 도구 이름은 기저 역량으로 번역하되, 호환성 자체가 요구인 경우 도구를 유지한다. 모호한 표현은 정규화해 없애지 말고 모호하다고 표시한다. 참여 자격 조항은 연구 역량이 아니다.

## RFP

발주 기관과 문서 버전은 알 때만 기록한다. 목표, 범위, 기술 성숙도, 산출물, 마일스톤, 평가 기준, KPI 정의와 단위, 기준선, 평가 데이터/프로토콜, 자원 한계, 예산/일정, 참여 자격, 데이터 접근, 권리, 보안을 추출한다. 요구는 원문 그대로 인용한다. 발주처의 수락 기준과 연구자의 탐색 지표를 분리한다. 없는 예산·수치 목표·법적 자격은 추론하지 않는다. KPI와 보유 장비의 모순은 기회 점수가 아니라 차단 요인이다.

## 요구 ID

원문 분석 안에서 REQ-NN을 매기고, 각각에 짧은 인용, 원문 위치, 명시/추론 표시, 정규화된 역량, 학습/구현/연구 분류를 붙인다. 기술적 차이를 뭉개지 않는다. RVV CPU 작업은 NPU SDK 작업이 아니고, 모델 파일 포맷은 양자화 알고리즘이 아니다.

## 작업의 세 수준

- 학습: 선행 개념 습득, 코드 읽기, 한정된 결과 재현.
- 구현: 지원 모델 포팅, 평가기 제작, 배포·테스트 하네스.
- 연구: 검증 가능한 미해결 질문에 답하기, 실패 조건 규명, 메커니즘 설명, 적절한 기준선 대비 개선 검증.

한 작업이 여러 수준에 걸칠 수 있다. 주 목적과 전환에 필요한 것을 표시한다. 새로움은 구현 노력이 아니라 문헌 비교로 판단한다.

## 근거 품질

원문 접근성/완전성, 원본/재게시, 게시일 신뢰도, 기관 다양성, 기술 구체성, 원문 간 일치/불일치를 기록한다. 독립 수요 그룹은 문서화된 규칙대로만 센다. 사용자가 고른 표본이 늘어난 것을 시장 점유율, 채용 전망, 수요 증가율이라 부르지 않는다. 추세 언급에는 기간과 표본 한계를 붙인다. '시장 전체'가 아니라 '수집된 자료에서 관찰됨'이라고 쓴다.

불일치는 유지한다. 저전력 임베디드 요구와 고처리량 서버 요구는 하나의 최선 방법이 아니라 별도 구성을 뜻할 수 있다. 제약을 완화한 새 버전이 옛 제약을 조용히 지우게 두지 않는다.

## 논문

`library/`에 등록한 뒤 `notes.md`를 채운다. 초록과 결론만 읽고 등록하지 않는다. 방법·실험 설정·한계 절을 읽는다. 결과 수치는 표·그림 번호와 함께 적는다. 코드·데이터 공개 여부와 버전(arXiv v?)을 기록한다. 논문의 주장과 본인 판단을 분리한다.
