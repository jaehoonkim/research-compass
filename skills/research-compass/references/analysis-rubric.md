# 분석·우선순위·실험 설계 기준

## 원문 보존과 읽기

- 사용자가 붙여넣은 본문은 UTF-8 텍스트로 저장한다. URL은 승인된 브라우징 도구로 가져와 본문과 URL을 함께 보존한다. 가져오기 실패는 읽은 것이 아니다. 검색 스니펫으로 RFP 전문을 대신하지 않는다.
- 작성자/기관, 게시일, 수집일, URL, 종류, 공개 여부, 읽은 범위를 분리해 기록한다. 모르면 null 또는 '미확인'. 수집일은 게시일이 아니다.
- PDF/DOCX/HWP/이미지는 세션이 실제로 제공하는 추출 도구를 쓴다. 표·그림·모호한 추출은 해당 페이지 이미지를 직접 본다. 페이지·절·줄 위치를 남긴다. 발췌만 있으면 범위를 표시하고 전체 결론을 피한다. 못 읽은 부분을 숨기지 않는다.
- 추가하기 전에 기존 기록과 비교한다. 스크립트는 같은 kind·organization의 정확 중복만 잡는다. 재게시·개정본은 `--related-to`/`--relation`으로 연결하고 새 수요 그룹으로 세지 않는다.

## 채용공고

역할·연차를 추출하되 직함을 기술로 등치하지 않는다. 필수/우대, 담당 업무, 특정 기술 제약, 팀 단위 성과를 구분한다. 도구 이름은 기저 역량으로 번역하되, 호환성 자체가 요구인 경우 도구를 유지한다. 모호한 표현은 정규화해 없애지 말고 모호하다고 표시한다. 참여 자격 조항은 연구 역량이 아니다.

## RFP

발주 기관과 문서 버전은 알 때만 기록한다. 목표, 범위, 기술 성숙도, 산출물, 마일스톤, 평가 기준, KPI 정의와 단위, 기준선, 평가 데이터/프로토콜, 자원 한계, 예산/일정, 참여 자격, 데이터 접근, 권리, 보안을 추출한다. 요구는 원문 그대로 인용한다. 발주처의 수락 기준과 연구자의 탐색 지표를 분리한다. 없는 예산·수치 목표·법적 자격은 추론하지 않는다. KPI와 보유 장비의 모순은 기회 점수가 아니라 차단 요인이다.

## 요구 ID

원문 분석 안에서 REQ-NN을 매기고, 각각에 짧은 인용, 원문 위치, 명시/추론 표시, 정규화된 역량, 학습/구현/연구 분류를 붙인다. 기술적 차이를 뭉개지 않는다. RVV CPU 작업은 NPU SDK 작업이 아니고, 모델 파일 포맷은 양자화 알고리즘이 아니다.

## 작업의 세 수준

- 학습: 선행 개념 습득, 코드 읽기, 한정된 결과 재현.
- 구현: 지원 모델 포팅, 평가기 제작, 배포·테스트 하네스.
- 연구: 검증 가능한 미해결 질문에 답하기, 실패 조건 규명, 메커니즘 설명, 적절한 기준선 대비 개선 검증.

한 작업이 여러 수준에 걸칠 수 있다. 주 목적과 전환에 필요한 것을 표시한다. 새로움은 구현 노력이 아니라 문헌 비교로 판단한다.

## 근거 품질

원문 접근성/완전성, 원본/재게시, 게시일 신뢰도, 기관 다양성, 기술 구체성, 원문 간 일치/불일치를 기록한다. 독립 수요 그룹은 문서화된 규칙대로만 센다. 사용자가 고른 표본이 늘어난 것을 시장 점유율, 채용 전망, 수요 증가율이라 부르지 않는다. 추세 언급에는 기간과 표본 한계를 붙인다. '시장 전체'가 아니라 '수집된 자료에서 관찰됨'이라고 쓴다.

불일치는 유지한다. 저전력 임베디드 요구와 고처리량 서버 요구는 하나의 최선 방법이 아니라 별도 구성을 뜻할 수 있다. 제약을 완화한 새 버전이 옛 제약을 조용히 지우게 두지 않는다.

## 후보 선별

외부 근거 / 개인 적합성 / 실행 가능성 / 기여 가능성 네 가지를 각각 상/중/하/미확인 + 이유 한 줄로 평가한다. 가중 합산 점수를 기본으로 만들지 않는다. 데이터·장비·예산·권한·사용자 명시 제외는 순위 전에 적용하는 하드 게이트다. 게이트가 실행을 막아도 이론 검토나 재현은 허용될 수 있다.

재사용 가능한 기반과 다룰 만한 첫 실험이 있는 주제를 선호한다. 기본 포트폴리오는 주 1 + 보조 1 제안, 나머지는 관찰 목록이다. 주 방향 변경은 명시 승인 전까지 제안이다. 공고에 가속기 이름이 나왔다고 장비 구매나 클라우드 지출을 권하지 않는다.

## 연구 카드로 변환

원문 요구 → 역량 → 기술 문제 → 반증 가능한 질문 → 가설 → 실험 → 결정의 사슬을 만든다. 측정하지 않은 성능 효과는 사실이 아니라 가설로 쓴다. 재현 / 구현 산출물 / 현상 분석 / 신규 방법 제안을 구분한다.

새로움을 주장하기 전에 승인된 웹 도구로 논문·코드·공식 문서를 확인하고 URL, 날짜, 버전, 겹치는 부분을 기록한다. 웹이 없으면 '새로움 미검증'으로 두고 해야 할 검색을 적는다. 가짜 인용을 만들지 않는다.

## 실험 설계

기준선, 주 독립 변수, 고정 조건, 주/보조 지표, 품질 가드레일, 반복·불확실성, 분리 실험(ablation), 교란 요인, 실패 기준, 산출물, 후속 분기를 포함한다. 일부러 약한 기준선이 아니라 기존의 최적화된 구현과 비교한다. 캘리브레이션 데이터와 평가 데이터를 분리한다.

추론 성능 작업에서는 커널 단독 / 런타임 벤치마크 / 종단 서비스 측정을 구분하고 서로 바꿔 쓰지 않는다. prefill/decode, 모델 메모리/캐시/작업 공간, 정확성/성능도 필요하면 따로 잰다. 현재 API, 지원 하드웨어, 양자화 포맷, 논문 주장은 구체적 구현 지시를 확정하기 전에 1차 출처로 확인한다.

## 실험 결과 기록

제공된 로그·노트·결과만 읽는다. 상태는 planned/running/completed/blocked/inconclusive. 장비, 모델 리비전, 소프트웨어 커밋, 데이터 분할, 명령, 원시 결과 경로, 반복 수, 불확실성을 받은 대로 보존한다. 관찰 / 해석 / 결정을 분리한다. 부정적 결과와 기각된 가설도 남긴다. 실험은 수요 신호 없이도 실행 가능성이나 다음 실험을 바꿀 수 있다.

## 결정 문장

"근거 A와 제약 B로 C를 유지/수정/보류한다. 가설 E와 F를 구분하려 D를 실행한다. G 이후 재검토." '변경 없음'도 정당한 결론이다. 부정적 결과와 포기한 접근은 이유와 함께 보존한다.
